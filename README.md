
## Как запустить

Для проекта рекомендуется Python 3.13.1. эта версия использовалась при разработке и тестировании

Команды запуска:

powershell
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
python run.py

После запуска приложение доступно в браузере:

text
http://127.0.0.1:5000/

## Структура проекта

### Корневые файлы

`run.py` — точка запуска веб-приложения Flask

`requirements.txt` — список зависимостей проекта

`check_profile.py` — проверка корректности JSON-профиля

`run_check.py` — запуск проверки документа из командной строки


### Папка app

`app/` содержит основной код веб-приложения

`app/__init__.py` создаёт Flask-приложение.

`app/routes.py` содержит маршруты веб-интерфейса: загрузку файлов, извлечение правил, проверку документа и выдачу результатов.

`app/templates/` содержит HTML-шаблоны страниц.

`app/static/` содержит CSS и JavaScript интерфейса.

### Папка app/models

`app/models/` содержит основные модели данных, через которые связаны части системы.

`document.py` описывает разобранный DOCX: абзацы, секции, таблицы, изображения, подписи и текстовые фрагменты.

`profile.py` описывает профиль проверки: `Profile`, `Rule`, категории правил и типы обязательности.

`violation.py` описывает одно найденное нарушение.

`check_result.py` описывает результат проверки: путь к отчёту, исправленному DOCX, DOCX с пометками и список нарушений.

### Папка app/parsers

`app/parsers/docx_parser.py` разбирает проверяемый Word-документ.

Он извлекает текст, стили, поля страницы, колонтитулы, таблицы, рисунки, подписи, списки, сноски и параметры абзацев. Результатом работы парсера становится объект `ParsedDocxDocument`, с которым дальше работают чекеры.

### Папка app/services

`app/services/` содержит сервисный слой приложения.

`check_service.py` — главный сервис проверки. Он загружает профиль, запускает парсер, передаёт документ в чекеры, фильтрует лишние нарушения и создаёт итоговые файлы.

`autocorrect_service.py` отвечает за автоисправление безопасных нарушений: основной текст, заголовки, подписи, таблицы, списки и часть типографики.

`review_docx_service.py` создаёт DOCX с комментариями Word по найденным нарушениям.

`paragraph_classifier.py` классифицирует абзацы: основной текст, заголовок, подпись, список, титульный лист и другие типы.

`parameter_registry.py` хранит русские названия параметров и связь параметров с объектами проверки.

`profile_utils.py` содержит вспомогательные функции для работы с правилами профиля.

`violation_grouping.py` группирует однотипные нарушения для отчёта, чтобы результат был читаемым.

### Папка app/checkers

`app/checkers/` содержит модули проверки документа. Все чекеры получают разобранный документ и профиль, а возвращают список нарушений.

`format_checker.py` проверяет основные параметры оформления: поля, формат страницы, шрифт, кегль, цвет, интервалы, отступы, заголовки, подписи, таблицы и рисунки.

`typography_checker.py` проверяет типографику: пробелы, тире, кавычки, знак номера, неразрывные пробелы, числовые диапазоны, единицы измерения и телефоны.

`structure_checker.py` проверяет структуру документа: состав работы, введение, заключение, список источников, содержание и скрытую нумерацию до введения.

`linguistic_checker.py` выполняет лингвистические проверки методичек через Natasha: задачи во введении, формулировки результатов и нежелательные фразы.

`consistency_checker.py` проверяет единообразие оформления однотипных элементов.

`section_consistency_checker.py` проверяет единообразие параметров секций документа.

### Папка app/extraction

`app/extraction/` содержит конвейер автоматического извлечения правил из нормативного документа. Это ключевая часть дипломной идеи.

`pipeline.py` запускает весь конвейер: сегментацию, построение утверждений, извлечение кандидатов, определение обязательности, проверку кандидатов и сборку профиля.

`segmenter.py` читает PDF/DOCX методички и разбивает текст на блоки, строки, таблицы и фрагменты.

`statement_builder.py` превращает фрагменты нормативного текста в атомарные утверждения.

`parameter_extractor.py` извлекает форматные правила: шрифт, кегль, поля, интервалы, выравнивание, отступы и другие параметры.

`structure_extractor.py` извлекает структурные и лингвистические требования: введение, источники, списки, заголовки, подписи и таблицы.

`modality_detector.py` определяет обязательность правила: обязательное, рекомендательное или допустимое.

`verifier.py` проверяет кандидаты на конфликты, неподдерживаемые параметры и сомнительные значения.

`patterns.py` хранит шаблоны и поддерживаемые параметры извлечения.

`models.py` описывает промежуточные модели извлечения: блок, утверждение и кандидат правила.

`presentation.py` содержит человекочитаемые подписи для интерфейса подтверждения правил.

### Папка app/reports

`app/reports/html_report.py` создаёт HTML-отчёт по найденным нарушениям.

### Папка app/templates

`app/templates/index.html` — главная страница приложения.

`app/templates/extract.html` — экран просмотра и подтверждения извлечённых правил.

`app/templates/result.html` — страница результата проверки.

### Папка app/static

`app/static/app.css` отвечает за визуальное оформление интерфейса.

`app/static/app.js` отвечает за работу интерфейса: переключение экранов, загрузку файлов, показ правил и работу с отчётом.

## Профили проверки

Профили хранятся в папке `profiles/`.

`profiles/gost_r_7_0_110_2025.json` — встроенный профиль ГОСТ Р 7.0.110-2025.

Профиль — это JSON со списком правил. Для проверяющих модулей не важно, откуда пришёл профиль: из встроенного файла, из ранее сохранённого JSON или из методички после извлечения.

## Папки с файлами пользователя

`uploads/` — рабочая папка для загруженных пользователем документов и временных данных извлечения.

`outputs/` — рабочая папка для HTML-отчётов, исправленных DOCX и DOCX с пометками.

Эти папки являются рабочими. Их содержимое создаётся во время использования приложения и не является основной логикой проекта.

## Документы по тестированию

Папка `docs/` содержит материалы для раздела тестирования диплома.

`testing_4_1_1_extraction.md` описывает оценку полноты автоматического извлечения правил из методички.

`testing_4_1_2_detection.md` описывает оценку точности обнаружения ошибок форматирования.

`testing_4_1_3_autocorrect.md` описывает тестирование автоисправления.

`testing_4_1_4_typography.md` описывает тестирование типографических проверок.

`testing_4_1_5_structure_linguistic.md` описывает тестирование структурных и лингвистических проверок.

`testing_4_1_full.md` содержит объединённую версию всех тестов для переноса в диплом.
